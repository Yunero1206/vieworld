- Implemented **P09 — Post-order, support requests, recovery without auto-grant**, strictly adhering to `docs/CONSTITUTION.md` (§2.3 "Non-auto-grant decoupling"), `docs/CONTRACTS.md` (§3.3, §7.2), `docs/packets/P09.md`, and deterministic domain invariants.
- Recorded architectural decision **DEC-008** in `docs/DECISIONS.md`: Explicit Decoupling of Customer Support Resolution and Source Record Reconciliation.
- Implemented SupportCase domain actions and pure state transitions in `src/domain/reducer.ts`:
  - `OPEN_SUPPORT_CASE`: Validates subject existence (`SUBJECT_NOT_FOUND` error if non-existent). If an active case (`open`, `acknowledged`, or `investigating`) exists for the subject, idemptotently returns it without creating duplicate cases.
  - `ACKNOWLEDGE_SUPPORT_CASE`: Transitions case from `open` to `acknowledged`.
  - `INVESTIGATE_SUPPORT_CASE`: Transitions case to `investigating`.
  - `RESOLVE_SUPPORT_CASE`: Sets status to `resolved`, records resolution metadata (`resolvedAt`, `summary`, `outcome`, `operatorId`), and updates `nextAction`. Strictly leaves underlying benefit/order state unmodified (Decoupling invariant).
  - `CLOSE_SUPPORT_CASE`: Transitions resolved case to terminal `closed` state.
  - `RECONCILE_BENEFIT`: Dedicated operational action that updates `benefit.status` to `eligible`, sets `reasonCode` to `RECONCILED_ORGANIZER_APPROVED`, and logs an audit event.
  - `RECONCILE_ORDER`: Dedicated operational action updating order resolution and dispatching source sync.
- Created reusable components and views:
  - `SupportCaseDetailView` (`src/views/SupportCaseDetailView.tsx`) mounted at `/support/:caseId`:
    - Full breadcrumb navigation, status badge, case ID, subject summary card, and next action advice.
    - Transparent 4-step update timeline (`Tiếp nhận` → `Xác nhận` → `Kiểm tra` → `Kết luận`) with demo time display.
    - Constitutional disclosure stating no fake business SLAs (e.g. 24h/48h) are promised.
    - Operator simulation desk allowing stepwise progression (`Acknowledge` → `Investigate` → `Resolve` with stated outcome → `Close`).
    - Separate Source Data Reconciliation section with explicit action button to unblock source records.
    - Recoverable not-found state when navigating to non-existent case IDs.
  - Integrated support entrypoints:
    - `BenefitDetailView`: Pending benefits show active case link or trigger to open reconciliation request.
    - `OrderDetailView`: Orders show support card with trigger to open or reuse an active support case.
    - `MyWorldView`: Added "Hỗ trợ & Đối soát" tab displaying user's support cases with status tags, next action steps, and direct navigation links.
