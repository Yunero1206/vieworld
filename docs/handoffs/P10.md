- Implemented **P10 — Notifications, Inbox, and read states**, strictly adhering to `docs/CONSTITUTION.md` (§2.3, §7.2), `docs/CONTRACTS.md` (§2, §3.3, §7.2), `docs/packets/P10.md`, and deterministic domain invariants.
- Recorded architectural decision **DEC-009** in `docs/DECISIONS.md`: In-App Truthful Notification Architecture and Category Opt-Out Invariants.
- Implemented pure notification reducers in `src/domain/reducer.ts`:
  - `MARK_NOTIFICATION_READ`: Sets `isRead: true` for a single notification.
  - `MARK_ALL_NOTIFICATIONS_READ`: Atomically marks all active notifications as read.
  - `UPDATE_NOTIFICATION_PREFERENCES`: Updates independent category preferences (`sessionReminders`, `capsuleReady`, `supportUpdates`, `orderUpdates`, `promotional`).
  - `CREATE_NOTIFICATION`: Validates category preference before adding to state.
- Integrated automated notification generation into core domain state transitions:
  - `TOGGLE_RSVP`: Adds session reminder (`session_reminder`, `sourceAttribution: 'session_system'`) when RSVP is toggled ON; automatically removes it when RSVP is toggled OFF. Cancelled sessions cannot receive reminders.
  - `END_SESSION`: Creates a `capsule_ready` notification when the session ends with live attendance recorded for the fan. Idempotent on repeated invocations.
  - `CREATE_ORDER` & `SIMULATE_FULFILMENT`: Generate `order_update` notifications tracking order creation and fulfilment.
  - `RESOLVE_SUPPORT_CASE`: Creates `support_update` notification with outcome findings linking to `/support/:caseId`.
  - `RECONCILE_BENEFIT`: Creates `support_update` notification alerting fan that the benefit is now eligible and linking to `/benefits/:benefitId`.
- Created UI components and views:
  - `InboxView` (`src/views/InboxView.tsx`) mounted at `/inbox`:

    - Unread counters, individual "Đã đọc" buttons, and "Đánh dấu đã đọc tất cả" bulk button.
    - Transparent attribution badges (`[Hệ thống VieWorld]`, `[Ban tổ chức]`, `[Sân khấu trực tiếp]`).
    - Dedicated "Cài đặt nhận tin" subpanel allowing fans to independently opt out of any notification category.
    - Clear constitutional disclosures: 100% in-app, zero browser push requests, no email/SMS collection, no fake personal 1-on-1 artist messages.
    - Direct action buttons linking to target objects (`/sessions/:id`, `/orders/:id`, `/support/:id`, `/benefits/:id`, `/me`).
